# Retrieval Evaluation v1.1 结果

本文负责记录 v1.1 固定检索评测的可复查结果、失败模式和配置结论。运行方法与数据维护规则统一见 [README.md](README.md)，本文件不保存逐次调参日志。

## 范围与限制

- Synthetic Dataset：48 条 Query，dev 32 条（30 条可回答、2 条负样本），holdout 16 条（14 条可回答、2 条负样本）。
- Project-realistic Acceptance Set：12 条 Query，语料来自公开 TraceMind 源码和当前文档，只在参数锁定后运行，不参与调参。
- Query Rewrite Dataset：12 条对话 Query，dev 8 条、holdout 4 条；只使用合成历史调用当前配置的 ChatModel。
- Embedding：`Qwen/Qwen3-Embedding-0.6B`；Reranker：`Qwen/Qwen3-Reranker-0.6B`。
- 默认检索配置：Hybrid、TopK 5、Dense threshold 0.50、Dense / Sparse prefetch 20 / 20、Reranker 关闭。
- dev 只有 30 条可回答 Query，holdout 只有 14 条。下文同时报告 query count 和发生变化的 Query 数，不对 0.01～0.02 级差异作超出样本分辨率的统计解释。
- 延迟来自本机实测，受模型冷启动、缓存和当时机器负载影响；质量矩阵中的缓存运行不用于跨配置延迟结论。

## Reranker

候选数 5、10、15、20 均实际运行。candidate 5 的 dev 结果最好：将 `syn-008`、`syn-015`、`syn-028` 的首条相关证据提升到 rank 1，没有 dev loss。candidate 10/15/20 没有额外 Top Rank 收益，并把 `syn-002` 的相关证据排出 Top 10；因此扩大 Reranker 候选池没有数据依据。

独立冷运行中，Reranker-5 的 total mean / p50 / p95 为 7144.7 / 7135.3 / 8304.7 ms，Reranker 阶段 p95 为 2955.1 ms。默认 Hybrid 的 total mean / p50 / p95 为 4681.2 / 4588.0 / 5531.4 ms；Reranker-5 的 total p95 增加 2773.3 ms（约 50.1%）。

dev 的提升没有在 holdout 复现，故不建议默认启用，详见“Holdout 与最终选择”。

以下是可用于延迟判断的冷运行，单位为 ms。质量矩阵为减少重复 Embedding 使用了进程内 Query cache，其接近零的 embedding latency 不参与此表。

## Query Rewrite

| Split | Query count | improved | worsened | unchanged | fallback | semantic drift |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| dev | 8 | 4 | 0 | 4 | 1 | 0 |
| holdout | 4 | 1 | 0 | 3 | 2 | 0 |

Rewrite 对省略类、指代类问题有帮助，但不稳定：holdout 只有 1/4 改善，2/4 在 15 秒超时后回退原 Query。观测延迟为约 4.9～15.0 秒。`rw-007` 即使改写后仍未命中，`rw-009` 虽将旧版 retry policy 补入 Query，仍未满足 Gold Evidence。当前实现的 fallback 能避免已观察到的检索回归，但不应把该小样本解释为改写一定安全；需要优先验证模型服务延迟和超时率。

## Failure Analysis

| 类别 | 观察数量 | 典型 Query | 证据与下一步 |
| --- | ---: | --- | --- |
| 单路 Recall failure | Dense 1；BM25 1（dev 30） | `syn-002`、`syn-015` | Hybrid 已覆盖，支持保留双路召回 |
| Hybrid Top-rank 不足 | 7（dev 30） | `syn-008`、`syn-014`、`syn-028` | 均在 Top 5，属于排序问题，不是候选池缺失 |
| 相似内容干扰 | 1（holdout 14） | `syn-037`“完整流式流程的最终状态有哪些？” | Top 5 返回同主题 runtime 文档，但没有包含稳定状态枚举的 `docs/api-contract.md`；需单独验证标题/路径/精确短语信号 |
| Reranker ranking loss | candidate 10/15/20：1（dev 30）；holdout：1（14） | `syn-002`；holdout `syn-033` | 扩大候选会引入干扰；holdout 一升一降，净指标为零 |
| Query Rewrite 未改善或回退 | dev 4/8；holdout 3/4 | `rw-007`、`rw-009`、两条 timeout | 区分改写质量与远程模型超时，扩大固定对话集后再判断 |
| Negative false-positive retrieval | dev 2/2；holdout 2/2 | 两个 split 的负样本 | Negative Empty-Result Rate=0，Negative Retrieval Rate=1；Retrieval-only 当前不负责最终拒答，应在完整 RAG Pipeline 另测 `terminal_status=no_answer` |

没有观察到 path/scope filter 越界；Runner 会校验隔离 collection 与 source path。当前 synthetic 语料采用与生产一致的单层 deterministic chunking，本轮未发现可独立归因的 chunk boundary failure。

## Holdout 与最终选择

参数在 dev 后锁定为“Hybrid + Reranker-5”，随后仅运行一次 baseline 与 candidate holdout。

| Holdout | Hit@1 | Hit@5 | Recall@10 | MRR@10 | Negative Empty-Result Rate | Negative Retrieval Rate | Total p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Hybrid baseline | 11/14 (0.7857) | 13/14 (0.9286) | 0.8929 | 0.8452 | 0/2 | 2/2 | 5066.1 ms |
| Hybrid + Reranker-5 | 11/14 (0.7857) | 13/14 (0.9286) | 0.8929 | 0.8452 | 0/2 | 2/2 | 7687.1 ms |

所有 aggregate 质量指标均为 Δ=0.0000（query_count=14）。Hit@1 与 MRR@10 都是 improved_queries=1、worsened_queries=1：`syn-035` 改善、`syn-033` 恶化；Hit@5 和 Recall@10 均为 improved_queries=0、worsened_queries=0。total p95 增加 2621.0 ms（query_count=16，约 51.7%）。dev 的 Reranker 收益未在 holdout 复现，因此 Final Candidate 回退为现有默认 Hybrid，不修改生产配置。

## Project-realistic Acceptance

锁定最终配置后，对 8 份公开 TraceMind 文件上的 12 条 Query 运行一次验收：Hit@1=5/12（0.4167），Hit@5=8/12（0.6667），Recall@10=0.6667，MRR@10=0.5069。该集合没有负样本，因此不报告负样本率。

4 条未满足 Top 5 Gold Evidence 的 Query 为 `acc-001`、`acc-006`、`acc-009`、`acc-012`。其中 `acc-001` 已返回 README 的“目录与架构”相关章节，但多证据 Query 未同时覆盖全部要求；另外 3 条是 generation eligibility、RRF 实现和 Cross-Encoder candidate text 等具体实现证据未进入 Top 5。该结果与 synthetic holdout 分开报告，也没有用于反向调整参数。

## 最终配置与回归结论

保持现有生产默认值：

```text
retrieval mode        = Dense + BM25 + application-side deterministic RRF
top_k                 = 5
semantic threshold    = 0.50
dense prefetch        = 20
sparse prefetch       = 20
reranker              = disabled
rerank candidate limit= 10（仅在显式启用时生效）
```

`backend/evals/retrieval/baselines/hybrid_v1_1.json` 冻结了 32 条 dev Query 的 query-level 基线。后续修改 Embedding、BM25、RRF、Reranker、TopK、Threshold、Query Rewrite、Chunking、Qdrant 或 Retrieval filtering 后，按评测 README 重建隔离 fixture、生成同 split summary，再运行 `compare --fail-on-regression`。比较结果中的每项 aggregate Δ 都带 query_count 和 improved / worsened / unchanged queries。

本轮没有运行完整 RAG Pipeline，因此没有 `No-Answer Accuracy` 结论；该指标必须另用 `terminal_status` / `no_answer` 进行端到端评测。
