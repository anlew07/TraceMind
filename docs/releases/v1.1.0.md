# TraceMind v1.1.0

TraceMind v1.1.0 在 v1.0 日常知识闭环上增加已验证知识检索、本地数据恢复、LangGraph RAG 流程和中文优先的工作区。它仍是本地优先的个人知识系统，不是自主编程或图检索产品。

## 主要变化

### 已验证知识检索

- Verified KnowledgeEntry 与 Document Chunk 一起参与默认 RAG。
- Knowledge 索引使用维护后的 Question、Background、Root Cause、Solution、Failed Attempts 和 Tags，不索引原始 assistant answer snapshot。
- Document 与 Knowledge Evidence 保持不同来源身份，共用 `[Sx]` Citation 契约。
- 编辑内容或改变验证状态会立即使旧 active generation 失效；Celery 幂等重建派生索引。

### 本地数据恢复

- Knowledge Base Archive 导出 PostgreSQL 事实记录、全部 DocumentVersion 原文件、Conversation、Message、KnowledgeEntry 和安全 Evidence Snapshot。
- Restore 在原子恢复 Source of Truth 前校验归档结构、大小限制、Checksum、实体关系、路径和冲突。
- Consistency Audit 检查 PostgreSQL、Local Storage、Qdrant Generation / Payload 与 Restore Journal。
- Safe Repair 使用后端 allowlist、最新审计重验、dry-run、operation lease 和修复后验证。
- Rebuild Derived State 重新解析全部 DocumentVersion，只索引每个 Document 最新版本和当前 verified KnowledgeEntry。
- PostgreSQL 长期业务数据与 Original Files 是持久事实来源；DocumentChunk、Qdrant 和任务运行状态可重建。

### LangChain + LangGraph RAG

- Production Generation 通过 LangChain ChatModel 使用现有 OpenAI-compatible 配置。
- 编译后的 LangGraph 编排确定性路由、Scope、Conversation-aware Query Rewrite、Hybrid Retrieval、可选 Reranker、Context、Grounded Generation、Citation 校验、No-answer 与 Finalize。
- Query Rewrite 超时、模型错误或无效结构化响应时回退原始 Semantic Query。
- Reranker 失败时保留 Hybrid Top-K fallback。
- LangGraph Custom Stream 映射为产品 SSE 事件，并保持 Conversation 完成、取消与安全错误语义。
- Execution Trace 只暴露阶段、状态、耗时、候选数、来源数和 fallback metadata，不暴露模型内部推理过程。

### UI 改版

- 采用中文优先、Evidence-led 的视觉系统，使用暖色阅读面、紧凑导航和渐进式 L3 调试信息。
- `/` 增加首次 Landing 入口，之后进入日常 Knowledge Base Workspace。
- 重做 Conversation、Documents、Knowledge、Knowledge Detail 与 Knowledge Map。
- 增加独立 Retrieval Workspace，用于查看 Semantic、Hybrid 与 Reranked 候选。
- 增加 Data & Recovery，用于 Archive、Restore、Audit、Repair 与 Rebuild。
- Global Shell 与 Contextual Inspector 支持桌面、平板和移动端。

### CI 与版本稳定性

- 修复 Data Maintenance 前端测试在 CI 环境中的差异。
- Backend、Frontend、Docker Image 和示例配置版本统一为 `1.1.0`。
- 当前文档收敛到稳定 Product 路径、开发指南、设计文档、Retrieval Evaluation 与 Release Notes。

## 相对 v1.0.0 的架构变化

- 新 Migration 增加 KnowledgeEntry 索引状态、持久化 Knowledge Base Rebuild Operation、Audit Snapshot / Repair Operation 与 Repair Lease / 删除语义。
- RAG 编排从旧 Service Pipeline 移到 `backend/app/rag/graph/`；TraceMind Domain Service 继续负责 Retrieval、Conversation Persistence、Citation 和基础设施边界。
- Document 与 Knowledge Point 共用一个 Qdrant Collection 和一次 Query Embedding，PostgreSQL Active Generation 决定可检索 Point。
- Qdrant 分别返回 Dense 与 BM25 分支，应用层执行确定性 RRF，再进入可选 Cross-Encoder。
- Restore、Repair 与 Rebuild 使用持久化 Operation、Generation / Lease Fencing 和显式 Retry，不把 Celery Task ID 当作事实来源。

## 升级与迁移说明

1. 升级前备份 PostgreSQL 与 Original Files。
2. 按锁文件更新依赖并执行 Migration：

   ```bash
   cd backend
   uv sync --frozen
   uv run alembic upgrade head
   ```

   ```bash
   cd frontend
   npm ci
   ```

3. v1.1.0 发布时 Alembic Linear Head 为 `20260817_0014`。从 v1.0.0 升级会应用：

   - `20260814_0011_add_knowledge_entry_indexing`
   - `20260814_0012_add_knowledge_base_rebuild`
   - `20260817_0013_add_consistency_repair`
   - `20260817_0014_seal_consistency_repair`

4. 存量 KnowledgeEntry 不会被隐式视为可信；只有 verified、版本当前且索引成功的条目参与 RAG。
5. Restore 只恢复 Source of Truth，派生状态从 pending / not-started 开始；需要执行 Rebuild 才能完整参与检索。
6. Qdrant 仍是派生数据。不要仅为应用数据库 Migration 而替换现有 Collection；派生状态缺失或不一致时使用 Audit / Rebuild。
7. 本地 `.env` 覆盖仓库默认值；旧环境需要自行更新 `APP_VERSION=1.1.0`，但不要提交该文件。

## 当前限制

- PDF 只读取可提取文本层，不支持 OCR。
- 代码使用确定性文本解析和行范围 Citation，不提供 AST、Symbol Scope 或调用图。
- Chunking 是单层确定性切分，不提供多层分块或自动合并。
- CPU-only Embedding 与 Cross-Encoder 可能带来明显延迟，首次模型下载或加载更慢。
- Knowledge Map 面向个人数据规模，不提供大图分页、聚类或图检索。
- 远程 OpenAI-compatible LLM 会接收问题、必要会话历史和选中的 Evidence 内容。
- TraceMind 不提供自主编程、通用 Agent、云备份或多租户权限能力。
