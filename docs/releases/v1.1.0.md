# TraceMind v1.1.0

TraceMind v1.1.0 extends the v1.0 daily-use knowledge loop with verified knowledge retrieval, recoverable local data, a LangGraph production RAG pipeline, and a redesigned Chinese-first workspace. It remains a local-first personal knowledge system, not an Agent or GraphRAG product.

## Highlights

### Verified Knowledge Retrieval

- Verified `KnowledgeEntry` content now participates in default RAG alongside Document chunks.
- Knowledge indexing uses maintained Question / Background / Root Cause / Solution / Failed Attempts / Tags, not the original assistant answer snapshot.
- Document and Knowledge evidence keep distinct source identities while sharing the same `[Sx]` Citation contract.
- Updating or changing validation status immediately invalidates an outdated active generation; Celery rebuilds the derived index idempotently.

### Local Data Durability

- Knowledge Base Archive exports PostgreSQL source records, all DocumentVersion original files, Conversations, Messages, KnowledgeEntries and safe Evidence snapshots.
- Restore validates archive structure, limits, checksums, entity relationships, paths and conflicts before atomically restoring Source of Truth.
- Consistency Audit checks PostgreSQL, local Storage, Qdrant generations/payload and Restore journals without changing data.
- Safe Repair uses a backend allowlist, latest-audit revalidation, dry-run plans, operation leases and post-repair verification.
- Rebuild Derived State reparses every DocumentVersion, indexes only each Document's latest version, and indexes current verified KnowledgeEntries.
- PostgreSQL source records plus Original Files remain persistent Source of Truth; Qdrant and parsed/index state remain rebuildable Derived State.

### LangChain + LangGraph Production RAG

- Production generation now uses a LangChain ChatModel behind the existing OpenAI-compatible configuration.
- A compiled LangGraph coordinates deterministic routing, scope resolution, conversation-aware Query Rewrite, Hybrid Retrieval, optional Reranking, context preparation, grounded generation, Citation validation, no-answer and finalization.
- Query Rewrite timeout, model error or invalid structured output falls back to the original semantic query.
- Reranker failure keeps the existing Hybrid Top-K fallback.
- LangGraph custom streaming maps to the product's SSE events and preserves Conversation completion, cancellation and safe error semantics.
- RAG Execution Trace exposes stages, statuses, latency, candidate/source counts and fallback metadata only. It does not expose private chain-of-thought.

### UI Redesign

- Chinese-first, evidence-led visual system with warm editorial surfaces, compact navigation and progressive L3 diagnostics.
- Landing first-entry flow at `/`, followed by the daily Knowledge Base Workspace.
- Redesigned Conversation, Documents, Knowledge, Knowledge Detail and Knowledge Map experiences.
- Added a dedicated Retrieval Workspace for Semantic / Hybrid / Reranked candidate inspection.
- Added a Data & Recovery workspace for Archive, Restore, Audit, Repair and Rebuild.
- Responsive Global Shell and contextual Inspector behavior across desktop, tablet and mobile widths.

### CI and Release Stabilization

- Data maintenance frontend tests were stabilized for CI environment differences.
- Current backend, frontend, Docker image and example configuration version declarations are aligned to `1.1.0`.
- Current documentation now has a stable Product path, one official Architecture, an explicit Current/Historical hierarchy and canonical repository links.

## Architecture Changes from v1.0.0

- New migrations add KnowledgeEntry indexing state, persistent Knowledge Base rebuild operations, audit snapshots/repair operations, and sealed repair lease/deletion semantics.
- RAG orchestration moved from the legacy service pipeline to `backend/app/rag/graph/` while TraceMind domain services continue to own retrieval, Conversation persistence, Citation and infrastructure boundaries.
- Document and Knowledge points share one Qdrant collection and one query embedding. Active generations from PostgreSQL decide which points are eligible.
- Dense and BM25 branches are fetched from Qdrant and fused by deterministic application-side RRF before optional Cross-Encoder reranking.
- Restore, Repair and Rebuild use persisted operations, generation/lease fencing and explicit retry semantics rather than treating Celery task IDs as source of truth.

## Upgrade / Migration Notes

1. Back up PostgreSQL and Original Files before upgrading an existing installation.
2. Update dependencies from the locked files:

   ```bash
   cd backend
   uv sync --frozen
   uv run alembic upgrade head
   ```

   ```bash
   cd frontend
   npm ci
   ```

3. The linear Alembic head is `20260817_0014`. Upgrading from v1.0.0 applies:

   - `20260814_0011_add_knowledge_entry_indexing`
   - `20260814_0012_add_knowledge_base_rebuild`
   - `20260817_0013_add_consistency_repair`
   - `20260817_0014_seal_consistency_repair`

4. Existing KnowledgeEntries start without a current verified index unless later validation/edit/retry has already queued synchronization. Only verified, current, successfully indexed entries participate in RAG.
5. A restored archive contains Source of Truth but intentionally starts with pending/not-started derived state. Run Rebuild before expecting restored data to be fully retrievable.
6. Qdrant remains derived data. Do not replace an existing collection merely to apply the database migrations; use Audit/Rebuild when derived state is missing or inconsistent.
7. Existing local `.env` files override repository defaults. Update `APP_VERSION=1.1.0` if an older local file still reports v1.0.0; do not commit that file.

## Known Limitations

- PDF ingestion reads extractable text only; OCR is not implemented.
- Code files use deterministic text parsing and line-range citations, not AST, Symbol Scope or call graphs.
- Chunking is single-level deterministic chunking; no hierarchical chunking or auto-merging is implemented.
- CPU-only Embedding and Cross-Encoder Reranking can add noticeable latency; first model download/load is slower.
- Knowledge Map targets personal data sizes and does not provide graph retrieval, large-graph pagination or clustering.
- Remote OpenAI-compatible LLM use sends the question, necessary conversation history and selected Evidence content to the configured Provider.
- TraceMind is not a Coding Agent, general Agent platform, GraphRAG product, cloud backup service or multi-tenant enterprise system.
